# OSM:select-model

Receive the accepted work and continuation from the [shared task-result decision](../osm/references/lifecycle.md).
This skill owns model/reasoning suitability, not the deliverable, destination
choice or handoff procedure. Return capability/cost gaps to that shared decision.
Assess during substantive Spec and reconcile before Build; reuse current evidence.
Mechanical work needs only a brief check. This does not enable native Plan mode.

## Assess remaining judgment

Take a second look at the accepted Spec and specialist outputs: what is settled,
overlooked or still needs judgment? Give a reasoned recommendation, not a score,
fixed threshold or mandatory separate reviewer. Select for the work still ahead
after Spec/Review. READY/PASS does not make Build/Ship mechanical.

Consider unsettled choices, consequences, context dependence and proof. Visual
direction, composition, narrative, voice, architecture and interacting constraints
may still require strong reasoning. Approved components, templates or formatting
settled content may suit a cheaper route. Phase, domain or volume alone selects
no model. Unexpected decisions reopen suitability and affected Spec/Review.

## Discover and compare

Reuse current runtime evidence; inspect models/providers, efforts, tools and
controls only for an unresolved suitability gap. Separate active settings,
new-task defaults and worker controls. Defaults do not prove the
active model; catalogs prove neither access nor authority. Respect explicit choices.
Do not invent equivalent reasoning tiers across providers or unsupported controls.

Choose sufficient capability, then total task cost: context, reasoning, tools,
transfer, coordination, review and retries. Separate tokens, money and time;
follow owner priorities. Preserve useful context; cheaper inference alone proves
no net gain. Use [measurement](references/measurement.md) for performance claims
or authorized comparisons; pilots prove no universal default.

For a material evidence gap, make a bounded lookup: official capability,
reasoning and price documentation, then relevant measurements such as
[Vulcan](https://vulcanbench.com/), [Artificial Analysis](https://artificialanalysis.ai/),
[LiveBench](https://livebench.ai/) or [DeepSWE](https://deepswe.datacurve.ai/).
Record available date, version, effort, harness, task family and metric. Compare
like conditions; rank, price or effort alone proves no efficiency. Missing or
conflicting evidence lowers confidence without blocking a sufficient route.

## Return and apply within the selected work

For a new lead on unknown substantive work, prefer the newest well-supported,
most capable available general model with high reasoning, unless the owner
chose otherwise. This is a heuristic; resolve model/effort locally.

Return remaining judgment, model/effort, evidence, reason, application control
and gaps in the existing task contract. Low judgment permits a cheaper candidate,
not automatic delegation. A material capability or cost gap reopens the shared
task-result decision. [Orchestrate workers](../osm-orchestrate-workers/SKILL.md)
uses this recommendation only for already selected delegated execution.

Apply an authorized exposed in-session switch when appropriate. If only the
user can switch, provide context and exact selection; require native readback to
claim application. A selected handoff uses the lifecycle's [continuation](../osm/references/continuation.md).
No model recommendation grants sidebar-task, provider/account, spend or
configuration authority; obey explicit-model and new-task tool rules.

Keep inventories/benchmark tables in the task, never owner memory, templates,
synced configuration or this package. A chosen route/reason/date may be historical
evidence. Persist defaults only for authorized native setup changes, preserving
unrelated settings and verifying readback. Promise no automatic future tracking.
Reassess on changed runtime, scope, judgment or outcomes, not each phase.
