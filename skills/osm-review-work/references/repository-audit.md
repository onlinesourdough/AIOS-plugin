# Audit accumulated repository drift

Use for a requested holistic health check, milestone or suspected accumulated
drift. Audit the current repository's responsibility, not parity with its seed.
Read local AGENTS and only sources relevant to the requested scope; a docs audit
does not need a runtime or personal-context inventory.

Compare documentation and routes with actual commands, configuration,
interfaces, behavior and proof. Inspect ownership, data/trust boundaries,
release/operation truth, failure visibility and recovery where relevant. Flag
broken skill links, generic lifecycle copies, stale evidence, unsafe exposure
and unowned dependencies. Domain audits may add specialist criteria locally.

If currentness matters, record root, branch, credential-free remote, dirty state
and exact HEAD. Fetch the selected upstream read-only and compare the live
object: equal, ahead, behind or diverged. Cached refs and a clean working tree
do not prove live currentness. An unavailable fetch is an evidence gap; audit
does not reconcile or publish the repository.

Run relevant safe checks and state unavailable or unrun evidence. Return
PASS, REVISE or BLOCKED with findings, source locations and the smallest next
action. Do not edit the subject during Review. When the accepted task includes
fixes, return to Build in the same task and repeat affected Review afterwards.
