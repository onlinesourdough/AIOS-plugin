# Codex setup and dashboard

The normal Notion flow is: connect Notion, select the AI Operating Model, review
its overview in the panel, then press **Save pointer**. Reviewing or refreshing
the overview never writes Codex instructions. Only Save pointer, the Context
step's Save pointer button or a confirmed Settings context switch writes the
managed AIOS block, with the existing backup and revision checks.

The panel cannot read Notion pages itself. When the person selects a model or
asks to refresh its overview, read the model through the official Notion
connection in chat and register a dated snapshot with Context's
[overview procedure](../../aios-context/references/panel-links.md#operating-model-overview).
Ask them to refresh the panel. It shows the model, its own groups and links,
and separate lines for Notion connected, model read (snapshot time and revision)
and host pointer saved. None of these shows that a running agent has loaded
the model, that native Skills are enabled or that Memory exists. If sections
are ambiguous, show the listed sections and let the person choose once; do not
re-pick destinations or rewrite the model.

Earlier Docs, Skills and Memory links stay as secondary **Saved shortcuts** with
their values and Settings editing; new setups need not add them. Without an
overview, and for folder contexts, the four sections (Notion, Context, Skills,
Memory) work as before. Panel buttons never start a chat or agent.

AIOS and the official Notion plugin remain separate. Native status checks
installation, enablement and connection; Connected does not prove page access
or a complete business setup. Page selectors fetch names and navigation
metadata only.

For requested business onboarding, verify the home, reuse existing sources,
preserve Spaces and access, and prove a useful task. A consultant's client task
never changes their personal default, its overview or its links. Labels grant
no access. The panel stores names, links and the derived overview only; company
information stays in its source and the model in Notion stays canonical.
Earlier saves remain after a later failure. Stale edits keep their draft and
require reconciliation; they must never silently adopt a new revision.
