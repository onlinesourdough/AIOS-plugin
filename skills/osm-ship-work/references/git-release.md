# Deliver an independent repository through Git

Use only when Git delivery is part of the authorized result. A local-only
repository needs no invented remote or publication. Pin the reviewed commit,
tree, comparison base, target branch and credential-free remote. Preserve
unrelated work; use a clean isolated delivery worktree when needed.

Re-attest root, branch, staged/unstaged state and exact reviewed diff. Fetch
the exact upstream and compare its live object with the reviewed expectation.
Unexpected paths, remote drift or divergence return to scoped integration and
Review; do not force, reset or auto-rebase to make delivery pass.

Use a normal non-force push of only the reviewed commit to its authorized
branch. A tag, release, registry publication or deployment needs its applicable
existing authority. Read back the live branch and exact tag/artifact identity
afterwards and compare with the reviewed commit. An uncertain action needs
readback before retry.

For a package release, verify version declarations, the packaged file inventory,
consumer install and exposed entrypoints for the affected harness. For a
deployed product, use its local operational runbook for actual version, health,
critical journey and recovery proof. A source test is neither an installation
nor a deployment observation. Preserve the previous immutable release and use
supported scoped controls for rollback; product rollback does not restore data.
